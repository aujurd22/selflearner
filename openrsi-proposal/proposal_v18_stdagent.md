| Research Question | Scientific question | When a standard coding agent (the RSI-Harness default coding agent) works inside a Lean 4 / mathlib environment with retrieval over a parsed 181k-theorem library, does adding a **verification-and-novelty admission funnel** to its propose-check loop change the number of genuinely new, machine-verified lemmas it contributes — at zero cost to verification yield? |
| Research Question | Why this is scientific research rather than pure engineering optimization | The comparison is a pre-registered, two-arm ablation: gated (compile + axiom policy + novelty + non-triviality gates) vs compile-only — the agent, model, prompts, retrieval, budget, and environment are identical except one arm-switch flag. The result either way is informative: prior pilot data (3+3 runs, 2026-10-06) showed **zero net-novel lemmas in both arms** with a weak proposer, demonstrating the gate blocks pollution (name conflicts, trivial propositions, textbook restatements) but does not create discovery. Whether the gate changes the *contribution rate* of a standard coding agent at scale is open and falsifiable. |
| Research Question | Starting environment and artifacts | The Base snapshot vendors: (1) the propose-check loop (`propose_check.py`, `run_overnight.py`) with arm-switchable admission stack; (2) the immutable library: 181,316 parsed mathlib theorems (66,217 with full tactic proofs) in SQLite+FTS5, plus a 488-statement miniF2F competition corpus for retrieval; (3) mathlib4 sources with the full prebuilt olean cache (v4.35.0-rc3); (4) the Judge scorer (Lean re-verification + axiom policy + novelty adjudication + within-snapshot dedup). All hash-checked. |
